# TrustForge Skills v0.8.0

TrustForge v0.8.0 adds **signed evidence attestations** to CommitmentGuard.

The release extends the v0.7 evidence/provenance model with an optional Ed25519 trust layer so a completion contract can require that an evidence observation was signed by an explicitly trusted issuer/key pair.

## Highlights

- Ed25519 attestation schema v0.1.
- Canonical JSON hashing for observation values and provenance metadata.
- Signed binding for observation key, issuer, key ID, issue time, and optional expiry.
- Completion-policy fields for requiring attestations and allow-listing issuers/key IDs.
- External public-key trust registry, separate from the completion contract.
- `trustforge evidence sign` and `trustforge evidence verify-attestation`.
- `trustforge verify --trust-registry` integration.
- Fail-closed handling for malformed, tampered, expired, future-dated, unknown-key, disallowed-issuer, and disallowed-key attestations.
- Trust-registry path confinement to relative files inside the registry directory.
- Signed-evidence adversarial regression fixtures.

## Example

Sign an observation:

```bash
trustforge evidence sign \
  --input evidence.json \
  --key ci.passed \
  --private-key signer.pem \
  --issuer release-ci \
  --key-id 2026-09 \
  --issued-at 2026-09-12T00:00:00Z \
  --expires-at 2026-09-13T00:00:00Z \
  > signed-evidence.json
```

Verify it directly:

```bash
trustforge evidence verify-attestation \
  --input signed-evidence.json \
  --key ci.passed \
  --trust-registry trust-registry.json \
  --as-of 2026-09-12T01:00:00Z
```

Or require it in the full CommitmentGuard completion gate:

```bash
trustforge verify contract.json \
  --evidence signed-evidence.json \
  --trust-registry trust-registry.json \
  --as-of 2026-09-12T01:00:00Z
```

## Trust model

A valid signature proves that the holder of the corresponding Ed25519 private key signed the canonical attestation payload. It does **not** prove that the signer collected the underlying evidence correctly, that the signer was uncompromised, that the evidence was sufficient for the real-world requirement, or that the trust registry itself was distributed securely.

TrustForge v0.8 is therefore a signed-evidence primitive, not a complete PKI system.

## Deliberate boundaries

v0.8 does not include cloud KMS/HSM adapters, remote signing, certificate chains, transparency logs, or automatic revocation distribution. Those remain future integration layers.

Private signing keys should be kept outside repositories and evidence bundles. The included regression fixture stores only synthetic public verification material.

## Compatibility

CommitmentGuard keeps the v0.7 contract/evidence/report schema line and legacy nested evidence compatibility. Attestations are optional unless a contract explicitly sets `require_attestation: true`.

The floating `v0` ref remains on v0.7.0 until the canonical v0.8.0 release is published and verified.
