# TrustForge Skills v0.4.0

DataLease becomes a usable purpose- and destination-bound data minimization layer for AI agent tool calls.

## Highlights

### Purpose-bound minimum-necessary payloads

DataLease projects structured payloads through explicit `allow`, `redact`, and `deny` rules. Recommended policies use default deny and can hard-deny selected classifier labels such as `secret` before ordinary allow rules.

### HTTP and MCP interception

Reference sync/async adapters now enforce DataLease immediately before outbound dispatch:

- HTTP scheme, host, and method destination binding;
- MCP tool-name destination binding;
- purpose authorization;
- field projection/redaction;
- block-before-dispatch behavior for unauthorized or empty transfers.

### Pluggable classifiers

Trusted application code can supply domain-specific classifiers through an explicit Python interface. Custom findings carry label, detector, confidence, and optional reason metadata. Plugin failures fail closed.

DataLease deliberately does not support CLI dynamic imports of arbitrary classifier modules.

### Measurable classifier baseline

The release includes deterministic synthetic benchmark fixtures and CI regression gates. The primary 30-case baseline is approximately:

```text
precision = 0.913
recall    = 0.875
F1        = 0.894
exact     = 25 / 30
```

Known mismatches remain documented. A separate multilingual/domain fixture adds Vietnamese phone/email examples, IPv6, credential paths, and benign identifier-like values.

## Policy example

```yaml
version: "0.1"
purpose: send order summary to support tool
default_action: deny
hard_deny_classifiers: [secret]

destinations:
  http:
    schemes: [https]
    hosts: [support.example.com]
    methods: [POST]
  mcp:
    tools: [support.create_ticket]

rules:
  - id: order-summary
    paths: [order.id, order.status, items.*.sku, items.*.quantity]
    action: allow

  - id: customer-email
    paths: [customer.email]
    classifiers: [pii.email]
    action: redact
    strategy: email_domain
```

## Security model

DataLease reduces data disclosure at an explicit application trust boundary. It does not make a destination trustworthy, prove anonymization, control downstream retention, or provide regulatory certification.

The HTTP reference adapter governs its JSON application body. Transport headers, query parameters, multipart/streaming content, and data independently retrieved by a downstream tool remain outside the v0.4 policy surface.

## Compatibility

- Python: 3.10+
- Policy schema: `0.1`
- Built-in classifier label contract: documented in `contracts/datalease-classifier-labels.md`
- Latest prior stable release: `v0.3.0`

## Upgrade notes

`v0.4.0` adds `PyYAML>=6.0` as a runtime dependency for YAML policy support.

Existing SkillDiff GitHub Action usage remains compatible. The stable floating `v0` ref should be advanced to this release only after the GitHub Release is published and verified.
