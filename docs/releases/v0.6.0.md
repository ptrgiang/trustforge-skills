# TrustForge Skills v0.6.0

ReproCapsule is the focus of v0.6.0: portable, integrity-checked failure reproduction for coding agents and autonomous debugging workflows.

## Highlights

### Build portable reproduction capsules

```bash
trustforge reprocapsule build \
  --spec examples/reprocapsule/example-spec.yaml \
  --output .artifacts/reprocapsule
```

A capsule can contain the declared failing command, explicit input copies, SHA-256 integrity metadata, a sanitized trace, runtime fingerprint, and environment-variable presence metadata without raw environment values.

### Verify and replay failures

Integrity preflight is the default:

```bash
trustforge reprocapsule replay \
  --capsule .artifacts/reprocapsule
```

Execution requires explicit opt-in:

```bash
trustforge reprocapsule replay \
  --capsule .artifacts/reprocapsule \
  --execute \
  --fail-on-divergence
```

Replay decisions are `ready`, `reproduced`, `diverged`, or `blocked`. A reproduction can be checked against the declared expected exit code and an optional literal failure signature.

### Export Docker/devcontainer contexts

```bash
trustforge reprocapsule export-container \
  --capsule .artifacts/reprocapsule \
  --output .artifacts/reprocapsule-container
```

Export verifies capsule integrity before generating a self-contained context with a non-root runtime user, Dockerfile, devcontainer configuration, manifest, safe copied inputs, and sanitized trace.

### Replay inside Docker

```bash
trustforge reprocapsule replay-container \
  --capsule .artifacts/reprocapsule \
  --execute \
  --fail-on-divergence
```

Container replay applies conservative defaults including runtime network disablement, read-only root filesystem, capability drop, no-new-privileges, PID/memory/CPU limits, bounded timeouts, and sanitized stdout/stderr. Docker build instructions also run with build-network access disabled.

These controls reduce attack surface but are not presented as a complete sandbox. Docker daemon access remains privileged infrastructure, and stronger isolation can still be appropriate for hostile workloads.

### Gate sanitizer regressions

```bash
trustforge reprocapsule benchmark-redaction \
  --dataset evals/reprocapsule/redaction-benchmark.jsonl \
  --min-secret-recall 1.0 \
  --min-clean-specificity 1.0
```

The v0.6 release candidate fixes the two known misses exposed during development:

- quoted JSON secret fields such as `"refresh_token": "..."` are now sanitized;
- plain-English text such as `Bearer authentication should...` is no longer treated as a bearer credential by the release fixture.

The bundled adversarial fixture is gated at 1.0 case-level secret recall and 1.0 clean specificity. This is a regression baseline for that fixture, not a claim that arbitrary secrets are always detectable.

## Security boundaries

ReproCapsule intentionally keeps several boundaries explicit:

- capsule build does not execute the declared command;
- raw environment values are not captured;
- secret-like command arguments and sensitive credential paths fail closed;
- replay verifies packaged input/trace integrity before execution;
- host replay requires explicit `--execute`, uses `shell=False`, a temporary workspace, and reduced environment inheritance;
- container replay requires explicit `--execute` and applies conservative Docker runtime restrictions;
- replay output is sanitized before reporting;
- container replay is not a complete security sandbox;
- base-image availability and registry resolution remain external dependencies when an image is not already available locally.

## Compatibility

- Python: 3.10+
- ReproCapsule build spec schema: `0.1`
- ReproCapsule replay report schema: `0.1`
- Container export report schema: `0.1`
- Container replay report schema: `0.1`
- Existing SkillDiff, DataLease, FreshPlan, and CommitmentGuard interfaces remain available.

## Upgrade notes

No migration is required for existing v0.5 users. ReproCapsule is additive. The floating GitHub Action ref `v0` should only advance to this release after the release tag and stable validation are complete.
