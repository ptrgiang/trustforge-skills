# TrustForge Skills v0.3.0

TrustForge v0.3.0 is the first release intended to be consumed directly from GitHub Actions.

## Highlights

### SkillDiff now understands Python structure

The new Python AST detector complements lexical scanning and can resolve common aliases such as:

```python
import subprocess as sp
import requests as rq
from os import getenv as read_env

read_env("DEPLOY_TOKEN")
rq.post(endpoint, json=payload)
sp.run(["echo", "done"], check=True)
```

It also distinguishes `open()` modes and records normalized symbols, detector identity, source line, and confidence.

### Reusable GitHub Action

A repository can now run SkillDiff in CI without separately installing TrustForge:

```yaml
- uses: actions/checkout@v4
- uses: ptrgiang/trustforge-skills@v0
  with:
    before: fixtures/trusted-skill
    after: skills/candidate-skill
    fail-on: medium
    format: sarif
    report-path: artifacts/skilldiff.sarif
```

`v0` is the floating stable pre-1.0 action line. Security-sensitive workflows should pin an exact commit SHA.

### Better machine-readable evidence

v0.3 adds AST-backed findings to JSON and SARIF output, allowing downstream code-scanning and policy systems to preserve source locations and detector provenance.

## Validation

The project CI validates:

- Python 3.10;
- Python 3.12;
- Python 3.13;
- unit tests;
- CommitmentGuard smoke tests;
- the repository's own composite GitHub Action via `uses: ./`.

## Scope and limitations

SkillDiff remains a static review and triage tool, not a malware detector or proof of safety. v0.3 does not yet model transitive dependency behavior, runtime-downloaded code, binaries, heavily dynamic dispatch, or prompt-induced tool behavior without a static indicator.

## What is next

The next SkillDiff research milestones are JavaScript/TypeScript structured analysis, transitive dependency capability analysis, signed baselines, and behavioral canary replay. The wider TrustForge roadmap then moves toward DataLease, FreshPlan, and ReproCapsule.
